# dp_1012 場景建置參數調校（2026-10-16）

目的：為 `Maps/dp_1012.pcd`（10/15 處理過的匯出檔）找出 `pcd2sim.build_scene` 的最佳參數，要求：樓梯 A（西側樓梯間）和 D（p01 附近）的踏板要完整恢復成一階一階的平面、機器人要能爬；所有可達地板格子不出現 `stuck/no_ground`；地板平整；出生點正確。

## 1. 結論

- **建場景指令**（場景 `scenes/dp_1012`，`meta.json` 的 `build_args` 也記著）：
  ```bash
  python3 scripts/fix_pcd_plane.py Maps/dp_1012.pcd -o Maps/dp_1012_fixed.pcd
  docker/run.sh "python3 -m pcd2sim.build_scene --pcd Maps/dp_1012_fixed.pcd --out scenes/dp_1012 \
      --ground-min-cells 8 --ground-fill-guard 0.3 --ground-surface median --ground-peel 3 --ground-small-flat 100"
  ```
- **PCD 不是原始 SLAM 輸出**：24.7% 的點是 z = −0.952 的合成地面層（整張圖、完全平），真地板在 −0.65…−0.35 且已被壓成幾個離散高度（−0.519 主要、−0.353、−0.584、−0.720）。直接建場景，真地板每個掃描破洞都是掉到 −0.95 的坑。`scripts/fix_pcd_plane.py` 只在真地板沒點的欄位保留那層並抬到附近真地板高度（126 萬點補洞），其餘 187 萬點丟掉。planner 的 octomap 繼續用原檔。
- **預設參數會把樓梯吃掉**：踏板只有 24–36 格（`--ground-min-cells 30` 丟掉）、平台的長 / 補把它埋掉、豎板點和頂上的雜訊體素讓踏板格的高度變成一道緩坡而和平台連成一區、2–3 格深的踏板用自由平面擬合會變成約 27° 的小斜坡。對應四個新選項：`min-cells`、`fill-guard`、`surface median` + `peel`、`small-flat`。全部預設關閉，dp_1008 用預設值重建結果逐位元相同。
- **贏家 `mc8_flat100`**：四個樓梯框斜坡格子 0%，1F→2F 那段（A3）13 層、階高標準差 1.8 cm；D 三層樓共 34 層。開放地板缺陷 1.0%（基準 0.8%，多出來的 `step_up` 是新恢復的踏板在設定檔限制下被拒），腳下射線打不到東西 0.11%（基準 0.13%，dp_1008 文件記載 0.17%）。出生點 (0, 0) 落在 −0.40，沒被移動。
- **機器人限制**：`config/sim.yaml` 的 `max_step_up` 0.18 → 0.22、`max_slope_deg` 30 → 45（用 climb 重播驗證：A3 幾何失敗 1.0%，舊限制失敗 7.6%）。用新限制重新評估 `scenes/dp_1012`：開放地板缺陷 0.69%（no_ground 0、step_up 61、step_down 18、slope 7、collision 46，20,315 個有效取樣）、腳下射線打不到東西 0%；D、A1、A2 三個框 0 失敗，A3 剩 3.4%（collision 12、step_up 1）。**碰撞模型還不能爬樓梯**：`_blocked` 用不隨 pitch 傾斜的機身盒，前緣會撞到下一階豎板（A3 每 383 個取樣 12 次 collision）。要讓 sim 真的走上樓梯，得讓碰撞檢查跟著 pitch 傾斜，這不是建場景參數能解的。

## 4. 掃描

每個變體：建場景（約 26 s）+ `eval_scene.py --auto` + 4 個樓梯框（約 50 s）。指標：`planar` = 壓成平面的格子比例、`缺陷` = 有效取樣（機身放得下、四腳都在平板上）中 reset/_check 失敗的比例、`懸空` = 腳下 3×3 射線打不到東西的比例、每個樓梯框的層數 / 斜坡格比例（平板傾斜 > 12°）/ 原始可站立欄位有平板的比例。CSV：`results/sweep_dp_1012/stage1.csv`、`stage2.csv`（gitignore）。

## 5. 程式碼改動

- `scripts/fix_pcd_plane.py`（新）：合成地面層自動偵測（最擠的 2 cm 層、≥ 5% 的點、±2 cm 內佔 ±10 cm 內 80% 以上）、每 0.25 m 格的真地板高度圖（最低且 ≥ 格內最擠 bin 30% 的 5 cm bin）、3 m 內反距離加權抬高。
- `pcd2sim/ground.py`：`fill_guard`、`surface="median"`（加權中位數）、`peel`（主平面 + 連通塊遞迴）、`small_flat`（小區水平面）；`_fit_plane` 多回傳 inlier 遮罩；stats 多 `cells_guarded`。
- `pcd2sim/build_scene.py`：`--ground-min-cells / --ground-layers / --ground-grow / --ground-floor-tol / --ground-fill-guard / --ground-surface / --ground-peel / --ground-small-flat`；`meta.json` 記 `build_args`；修掉補洞格查 intensity 可能越界的 bug（建 dp_1012 時觸發）。
- `scripts/eval_scene.py`（新）、`scripts/sweep_scene.py`（新）：見 `usage.md` 2.2。
- `tests/test_fix_pcd_plane.py`、`tests/test_ground.py`（合成樓梯房間、fill_guard、small_flat）：container 內 28 passed / 5 skipped。
- `config/sim.yaml`：`scene: scenes/dp_1012`、`spawn: [0, 0, 0, -0.4]`、`max_step_up 0.22`、`max_slope_deg 45`。

## 6. 還沒做 / 下一步

- **處理過的 PCD 把 1F 地板切成台階**：真地板被壓成 −0.519（39.9 萬點）和 −0.353（9.8 萬點）兩個平面，xy 範圍幾乎重疊，交界處是 17 cm 的硬台階；10/13 原檔在同樣位置是連續的緩坡（原點 −0.45…−0.5、p01 −0.3）。出生點 (0, 0) 正好在交界上（x ≈ −0.5…−1 處從 −0.35 落到 −0.52），`bench.py` 靜止時 IMU 讀到 [0.20, −0.24, 0.95] g，機身傾約 15°；開放地板的 step_up 61 / step_down 18 多半是這些台階邊。這是匯出流程的問題，建場景參數救不了；要嘛匯出時不要把地板壓成離散平面，要嘛出生點移開交界（例如 (1, 0)）。
- `bench.py --scene scenes/dp_1012 --seconds 20 physics.rtf=0`：RTF 3.5×、199 幀、靜態幀 vs 地圖 NN 距離 P95 0.207 m、proxy 沒溢位；盲走正弦路徑撞牆 17 次（bench 本來就不避障）。

- 碰撞檢查隨 pitch 傾斜（`quadsim/sim.py _blocked`），否則機器人在樓梯上會被豎板擋住。
- 在 robot01 stack 上跑 `scripts/nav_goal_loop.sh --waypoints config/nav_waypoints_dp_1012_3pt.yaml --loops 3`，確認 `/sim/events` 零 stuck / collision；teleop 到 D 的樓梯口試爬。
